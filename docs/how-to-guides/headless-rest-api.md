# Headless WordPress & Decoupled REST API Guide

This guide explains how to fetch, configure, and render **GSlider Blocks** in modern decoupled frontend frameworks, including **Next.js (App Router)**, **Astro**, and **Remix**.

GSlider Blocks provides native REST API serialization powered by `BlocksController.php` and `BlockParser.php`. All block attributes and responsive `{ Desktop, Tablet, Mobile }` options are pre-parsed on the server into ready-to-use Swiper.js configuration objects (`swiperConfig`) and sanitized scoped CSS, eliminating runtime style calculation on your frontend.

---

## 🧭 Endpoints Reference

GSlider Blocks exposes two ways to access slider data:

### 1. Dedicated Endpoint (Recommended)

Retrieve all sliders embedded in a specific post or page:

```http
GET /wp-json/gslider/v1/blocks/{id}
```

- **Parameters:**
  - `{id}` (*integer*, required): The WordPress post or page ID.
- **Authentication:**
  - **Public published posts/pages**: No authentication required. Public visitors and headless build servers can fetch freely.
  - **Drafts, private posts, and pending posts**: Requires authentication with the post type's read capability (e.g. `read_post` via WordPress Application Passwords or JWT).
  - **Password-protected posts**: Denied (`rest_cannot_read_post`) until the valid password cookie is provided.

#### Example Request:
```bash
curl -X GET https://example.com/wp-json/gslider/v1/blocks/123
```

#### Example Response Payload:

### 2. Core WordPress REST Field (`gslider_blocks`)

If your headless frontend already fetches entire post entities from WordPress core endpoints, GSlider automatically embeds the parsed slider collection in the standard response:

```http
GET /wp-json/wp/v2/pages/{id}
GET /wp-json/wp/v2/posts/{id}
```

#### Response Structure:
```json
{
  "id": 123,
  "title": { "rendered": "Modern Digital Agency" },
  "content": { "rendered": "..." },
  "gslider_blocks": [
    {
      "blockId": "gslider-a1b2c3d4",
      "blockName": "gslider-blocks/image-slider",
      "sliderType": "slider",
      "totalSlides": 4,
      "swiperConfig": { ... },
      "css": "...",
      "slides": [ ... ],
      "attrs": { ... }
    }
  ]
}
```

> [!TIP]
> The `gslider_rest_field_post_types` filter in PHP allows adding custom post types (e.g. `portfolio`, `products`) to expose the `gslider_blocks` field automatically.

## 📐 Response Schema Definition

Each slider block object returned in `blocks` or `gslider_blocks` adheres to the following contract:

| Property | Type | Description |
| :--- | :--- | :--- |
| `blockId` | `string` | Unique scoped identifier (e.g. `gslider-a1b2c3d4`). Used for CSS scoping. |
| `blockName` | `string` | Gutenberg block name (e.g. `gslider-blocks/image-slider`, `gslider-blocks/testimonial`, `gslider-blocks/base`, `gslider-blocks/logo-carousel`, `gslider-blocks/flexi-content`). |
| `sliderType` | `string` | Transition mode (`slider` or `carousel`). |
| `totalSlides` | `integer` | Count of active slide items. |
| `swiperConfig` | `object` | Fully pre-parsed Swiper.js options ready to spread directly into `<Swiper {...swiperConfig}>`. |
| `css` | `string` | Scoped dynamic CSS rules generated by `styling.js` and sanitized against XSS on the server. |
| `slides` | `array` | Normalized array of slide objects (urls, titles, subtitles, reviews, logos, etc.). |
| `attrs` | `object` | Complete block attributes with default values filled in. |

## 🚀 Modern Integration: Next.js (App Router)

### 1. TypeScript Interfaces

Define the contract for the API response in `types/gslider.ts`:

```typescript
export interface GSliderSlide {
  id?: string | number;
  url?: string;
  alt?: string;
  caption?: string;
  link?: string;
  title?: string;
  subTitle?: string;
  description?: string;
  authorName?: string;
  authorDesignation?: string;
  ratingNumber?: number;
  [key: string]: unknown;
}

export interface GSliderBlock {
  blockId: string;
  blockName: string;
  sliderType: 'slider' | 'carousel';
  totalSlides: number;
  swiperConfig: Record<string, unknown>;
  css: string;
  slides: GSliderSlide[];
  attrs: Record<string, unknown>;
}

export interface GSliderResponse {
  post_id: number;
  post_title: string;
  total_sliders: number;
  blocks: GSliderBlock[];
}
```

### 2. Server Component Fetch Function

In your Next.js App Router project (e.g. `lib/wordpress.ts`), fetch slider data with Incremental Static Regeneration (ISR):

```typescript
import { GSliderResponse } from '@/types/gslider';

const WP_URL = process.env.NEXT_PUBLIC_WORDPRESS_URL || 'https://example.com';

export async function getSliderBlocks(postId: number): Promise<GSliderResponse> {
  const res = await fetch(`${WP_URL}/wp-json/gslider/v1/blocks/${postId}`, {
    next: {
      revalidate: 60, // Revalidate cached data every 60 seconds (ISR)
      tags: [`gslider-post-${postId}`],
    },
  });

  if (!res.ok) {
    throw new Error(`Failed to fetch GSlider data for post #${postId}: ${res.statusText}`);
  }

  return res.json();
}
```

### 3. Client Slider Component (Swiper React)

Create a dedicated client component `components/GSlider.tsx` using Swiper React:

```tsx
'use client';

import React from 'react';
import { Swiper, SwiperSlide } from 'swiper/react';
import { Navigation, Pagination, Autoplay, EffectFade } from 'swiper/modules';
import type { GSliderBlock } from '@/types/gslider';

// Import core and module Swiper styles
import 'swiper/css';
import 'swiper/css/navigation';
import 'swiper/css/pagination';
import 'swiper/css/effect-fade';

interface GSliderProps {
  block: GSliderBlock;
}

export function GSlider({ block }: GSliderProps) {
  const { blockId, swiperConfig, slides, css } = block;

  return (
    <div className={`gslider-wrapper ${blockId}`}>
      {/* Inject sanitized scoped dynamic CSS */}
      {css && <style dangerouslySetInnerHTML={{ __html: css }} />}

      <Swiper
        modules={[Navigation, Pagination, Autoplay, EffectFade]}
        {...swiperConfig}
        className="gslider-container"
      >
        {slides.map((slide, index) => (
          <SwiperSlide key={slide.id || index} className="gslider-slide">
            {slide.url && (
              <img
                src={slide.url}
                alt={slide.alt || ''}
                className="w-full h-auto object-cover"
                loading="lazy"
              />
            )}
            {slide.title && <h3 className="slide-title">{slide.title}</h3>}
            {slide.caption && <p className="slide-caption">{slide.caption}</p>}
          </SwiperSlide>
        ))}
      </Swiper>
    </div>
  );
}
```

### 4. Page Implementation (`app/page.tsx`)

Render the sliders in your React Server Component page:

```tsx
import { getSliderBlocks } from '@/lib/wordpress';
import { GSlider } from '@/components/GSlider';

export default async function HomePage() {
  const { blocks } = await getSliderBlocks(123); // Replace with your target Page/Post ID

  return (
    <main className="container mx-auto px-4 py-8">
      <h1 className="text-3xl font-bold mb-6">Featured Sliders</h1>
      
      {blocks.map((block) => (
        <section key={block.blockId} className="my-8">
          <GSlider block={block} />
        </section>
      ))}
    </main>
  );
}
```

## 🔒 Security, Sanitization & Cache Revalidation

1. **Server-Side CSS Sanitization**:
   - `BlockParser.php` runs all generated dynamic CSS and `blockStyle` rules through strict CSS sanitizers, eliminating `@import`, `javascript:`, expression injections, and script tags before serializing to JSON.
2. **On-Demand Cache Purging**:
   - In Next.js, use [On-Demand Revalidation](https://nextjs.org/docs/app/building-your-application/data-fetching/incremental-static-regeneration#on-demand-revalidation-with-revalidatetag) by triggering `revalidateTag('gslider-post-123')` via a WordPress `save_post` webhook.

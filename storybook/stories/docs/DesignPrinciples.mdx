# 📐 GSlider Design Principles & Engineering Standards

The GSlider Blocks Design System is engineered to feel like a native extension of the WordPress Gutenberg Editor while providing advanced responsive capabilities required for modern slider development.

---

## 1. 📏 Gutenberg Inspector Alignment

* **Spatial Constraint**: All 22 UI controls are designed specifically for the standard WordPress Inspector Sidebar width (**280px to 300px**).
* **Native Component Hierarchy**: Components inherit styles from `@wordpress/components`, honoring active WordPress core design tokens, typography, and contrast standards.
* **SlotFill Architecture**: Control compositions utilize `InspectorControls` and `SlotFillProvider` so that panels seamlessly mount into the editor sidebar without direct DOM manipulation.

---

## 2. 📱 Responsive-First State Architecture

Every visual attribute across GSlider Blocks supports an explicit 3-device breakpoint object schema:

```javascript
// Standard responsive object pattern
{
    Desktop: 48,
    Tablet: 36,
    Mobile: 24
}
```

### Breakpoint Matrix
* **Desktop**: `> 1024px` (Default base configuration)
* **Tablet**: `768px – 1024px` (Intermediate mobile tablet screen)
* **Mobile**: `< 768px` (Compact smartphone viewport)

When a user switches devices via `ResponsiveDeviceControl`, all responsive fields in the panel automatically synchronize their active input view to the selected device without mutating the values of other breakpoints.

---

## 3. 📦 Standardized Attribute Schemas

To ensure strict predictability and support automated migrations and headless REST parsing, all block attributes follow standardized naming conventions:

### A. 8-Key Spacing Schema
Used for all padding and margin controls (`<prefix>Padding...` or `<prefix>Margin...`):

```javascript
<prefix>PaddingUnits:           { Desktop: 'px', Tablet: 'px', Mobile: 'px' }
<prefix>PaddingDesktop:         { top: '30', right: '30', bottom: '30', left: '30' }
<prefix>PaddingDesktopCssStyle: '30px 30px 30px 30px'
<prefix>PaddingTablet:          { top: '20', right: '20', bottom: '20', left: '20' }
<prefix>PaddingTabletCssStyle:  '20px 20px 20px 20px'
<prefix>PaddingMobile:          { top: '15', right: '15', bottom: '15', left: '15' }
<prefix>PaddingMobileCssStyle:  '15px 15px 15px 15px'
<prefix>PaddingLink:            true
```

### B. 13-Key Typography Schema
Used for all typography controls (`<prefix>Font...`):

```javascript
<prefix>FontFamily:         'Inter'
<prefix>FontSize:           { Desktop: 32, Tablet: 26, Mobile: 20 }
<prefix>FontSizeUnits:      { Desktop: 'px', Tablet: 'px', Mobile: 'px' }
<prefix>FontWeight:         '700'
<prefix>FontStyle:          'normal'
<prefix>TextTransform:      'none'
<prefix>TextDecoration:     'none'
<prefix>LineHeight:         { Desktop: 1.4, Tablet: 1.4, Mobile: 1.3 }
<prefix>LineHeightUnits:    { Desktop: 'em', Tablet: 'em', Mobile: 'em' }
<prefix>LetterSpacing:      { Desktop: 0, Tablet: 0, Mobile: 0 }
<prefix>LetterSpacingUnits: { Desktop: 'px', Tablet: 'px', Mobile: 'px' }
<prefix>WordSpacing:        { Desktop: 0, Tablet: 0, Mobile: 0 }
<prefix>WordSpacingUnits:   { Desktop: 'px', Tablet: 'px', Mobile: 'px' }
```

### C. 3-Key Color Schema
Used for color customization with hover state transitions:

```javascript
<prefix>ColorSwitcher: 'normal' // 'normal' | 'hover'
<prefix>Color:         '#1e293b'
<prefix>ColorHover:    '#2563eb'
```

## 4. ⚡ Lean Inline CSS Delivery (Zero File-Writing)

* **No Disk I/O on Page Loads**: Dynamic styles generated by `styling.js` are serialized directly into the block's `blockStyle` attribute.
* **WordPress.org Compliant**: Styles are injected inline via `wp_add_inline_style()` by `StyleGenerator.php`. Writing temporary CSS files into `wp-content/uploads/` is completely eliminated.
* **Scoped Selectors**: All CSS rules are strictly scoped to the block's unique identifier (`#gslider-xxxxxxxx`), preventing stylesheet pollution.

---

## 5. 🛠️ Code Conventions & Import Best Practices

All inspector controls must be imported using standardized Webpack path aliases:

```javascript
// ✅ Correct: Using approved aliases
import ResponsiveSpacingControl from '@Components/responsive-spacing-control';
import ResponsiveTypographyControl from '@Components/responsive-typography-control';
import ColorControl from '@Components/color-control';
import { HORIZONTAL_POSITION_ICONS } from '@Constants';

// ❌ Incorrect: Relative path traversing
import ColorControl from '../../components/color-control';
```

---

## 6. ♿ Accessibility & WCAG 2.1 Compliance

* Every interactive element must provide an accessible label (`aria-label`, `label`, or `aria-labelledby`).
* Dropdown triggers and popovers must declare `aria-expanded` and respond to `Escape` key events.
* Drag-and-drop interfaces (`ContentOrderControl`) must maintain full keyboard reordering support via `@dnd-kit`.
* Color pickers and background controls must support high-contrast focus rings for keyboard navigation.
